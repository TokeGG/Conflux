# Dungeon rework D2: feel, scale, elements, economy, UI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline; the owner chose continuous execution). Steps use checkbox syntax. Every batch ends with a version bump and a push to `main`.

**Goal:** Fix what the owner found wrong while playing D1, then grow the game: bigger rooms and more, stronger mobs with depth; three elements at a time chosen at shops, with lightning and chain reactions; souls and shops; a proper Esc menu and a much nicer UI.

**Architecture:** Same layering as before (deterministic `shared/` sim and data; the client only reads state and sends inputs). Batch A changes input and movement; B changes generator and encounter numbers; C changes the element model from a fixed four to data-driven elements with a three-slot loadout; D adds economy rooms; E replaces the HUD and adds menus.

**Spec:** `docs/superpowers/specs/2026-10-22-dungeon-crawler-rework-design.md` (sections 3, 4, 5, 7), plus the owner's requests of 2026-10-23 recorded under Requirements below.

## Requirements (owner, 2026-10-23, verbatim in substance)

1. Space is a jump; Shift is the dash, and it must really dash, not blink.
2. A much better and nicer UI.
3. Switching element must work at any time, not only when no skill is cooling down.
4. Selecting an augment must not release the mouse from the game (pointer lock).
5. The player must not spawn inside a wall when entering a room.
6. Rooms larger; more mobs; mobs increase in number and strength the further you get.
7. An Esc menu with game options, settings and keybinds.
8. Element switching defaults to 1-2-3 and only three elements are available at a time; one shop option is picking a new element.
9. More elements, such as lightning, that mix with the others for more dynamic play; lightning chains between soaked enemies instead of the current Shock Chain.
10. Abilities and rooms are fine for now; later passes.
11. No delay at all when switching elements (the swap cooldown is already 0; if a delay is still felt it is in the animation or the HUD, to be found with the owner).
12. Where animations come from, and other feel numbers (camera, field of view, speeds), must be editable live in the dev panel.
13. No invert option and no developer checkbox: **accounts**, with the owner (and devs they grant) getting the dev/admin panel, as in MMO Arena and Aim Arena; copy that panel and its assets for this game. Needs a server (hosting decision below).

## Global Constraints

- `shared/` has no DOM, Three.js or art paths; randomness only from the seeded streams; Three.js pinned 0.164.1; versions below 1.0.
- Tests first; `npm run typecheck` and `npm test` before every push; every push bumps the version and goes to `main` as well as `claude/conflux-m0` (`.superpowers/finish.sh`, which runs the tests before pushing).
- Run the browser smoke (`npx tsx scripts/smoke.ts`) at the end of each batch and send the owner screenshots of anything visual.
- Owner-only and dev tools are never in patch notes. Unlocks and the tuned-run rule stay as they are.

## Review Focus

1. Jump and dash against walls, ceilings and gates: the player never ends inside a collider, and a dash cannot carry the player through a wall.
2. Rebinding a key to one already in use, or to a reserved key (Esc): the menu refuses or swaps, never leaves an action unbound.
3. A loadout with three of N elements: a skill, a swap key or a reaction that names an element the player does not hold must not crash the sim or the HUD.
4. A room with more mobs than spawn spots: spots are reused without stacking enemies in walls; the sim still ticks at 60 Hz with 40 enemies.
5. Pointer lock lost to any overlay (reward, shop, menu): it is asked for again from the click that closes the overlay.

## Batch A: controls and feel

### Task A1: Jump, real dash, new default keys
**Files:** `shared/src/types.ts` (`BTN.JUMP`), `shared/src/sim/player.ts`, `shared/src/sim/state.ts` (`PlayerState.vy`, `onGround`), `shared/data/player.json` (`jump: { speed, gravity }`, `dash` replaces `dodge` naming kept), `shared/src/sim/skills.ts` (dash skills move over time), `client/src/input.ts` (defaults: Space jump, ShiftLeft dodge-dash, KeyQ utility skill, KeyE interact), tests `shared/test/jump.test.ts`, `shared/test/dash.test.ts`, `client/test/input.test.ts`.
**Interfaces:** `Input.buttons & BTN.JUMP` starts a jump when on the ground; the player's `pos.y` follows a ballistic arc (default 1.1 m high, 0.7 s) and lands on `world.groundAt`; a dash (the generic one on Shift, and dash-shaped skills) moves the player at constant speed over its duration and stops at the first collider.
- [ ] Failing tests: jump peaks near 1.1 m and returns to the ground; no double jump; jump blocked while stunned; a dash covers its distance over its duration (not in one tick); a dash into a wall stops at the wall; a dash skill's trail still lands along the path; default bindings are Space = jump, Shift = dash, Q = utility.
- [ ] Implement; update the HUD key hints; bump; push.

### Task A2: Switch element at any time

### Task A3: Keep the mouse captured after a menu or reward click

### Task A4: No spawning in walls
**Files:** reproduce first with a smoke-style script that enters ten rooms and checks `world.blocked` at the player and that the camera origin is outside every collider; fix in `shared/src/gen/generate.ts` (start cell, clearance) or `client/src/camera.ts` (camera pushed into a wall at a corner); test `shared/test/gen.test.ts` (start clear at radius 1.2 and at 2.0 m from every wall, 500 seeds per theme) and `client/test/camera.test.ts` (camera never inside a collider when the player stands in a corner).

### Task A5: Esc menu with settings and keybinds
**Files:** create `client/src/hud/menu.ts`, `client/src/keybinds.ts` (load/save, `rebind(action, code)` refusing Esc and swapping on conflict); modify `client/src/main.ts`, `client/src/input.ts`, `client/src/settings.ts`; tests `client/test/keybinds.test.ts`.
**Interfaces:** `Esc` toggles a pause menu over the game (the sim pauses in a run; the page stays responsive): Resume, Controls (every action rebindable, shown with its current key), Game (mouse sensitivity, invert Y, field of view), Graphics (render scale, shadows, effects, max enemies), Quit run. Settings and bindings persist in `localStorage` (`conflux.settings`, `conflux.keys`).
- [ ] Failing tests: rebinding sets the key and persists; binding a key used by another action swaps the two; Esc cannot be bound; a corrupt saved binding set falls back to defaults; every action has exactly one key.
- [ ] Implement the menu with the new look from Batch E's style guide (plain for now); bump; push.

## Batch G: accounts and the owner panel (hosting decision first)

MMO Arena's design, ported: accounts (name and password, scrypt hash, sessions), reserved owner names that can only be registered with an owner code, per-account grants (`dev`), an admin panel with Players, Moderation, Permissions, Tuning (live data patches), Models (custom mobs and their files stored on the server so every player sees them) and Log tabs; the dev panel is shown only to the owner and to accounts granted `dev`. Needs a Node server (Render, like the other games) and a store (Upstash Redis), which the owner creates; secrets stay in the host's environment.

- [ ] Implement; balance report (bot) to check the curve is survivable for several rooms; bump; push.
