# Conflux M0 to M3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Conflux up to its first complete playable: a third-person elemental action roguelite in the browser with a dev panel, from empty repo to a full room-to-room run (M0 foundation, M1 player, M2 enemies and mob import, M3 run loop).

**Architecture:** A TypeScript npm-workspaces monorepo. `shared/` holds the deterministic 60 Hz simulation and all game data as JSON (no DOM, no Three.js); `client/` runs the sim in a Web Worker and renders it with Three.js through a data-driven render profile; a dev panel edits data through layered patches. Everything the sim knows about art is a logical ID resolved by an asset manifest.

**Tech Stack:** TypeScript 5, Vite 5, three 0.164.1 (pinned: r175 broke FBX rendering), `node:test` run through `tsx`, `@gltf-transform/core` and `meshoptimizer` for model import, `sharp` and `fake-indexeddb` as test-only helpers, `playwright-core` with the preinstalled Chromium for browser smoke tests.

**Spec:** `docs/superpowers/specs/2026-10-17-conflux-design.md` (section numbers below, "§", refer to it).

## Global Constraints

- Sim: fixed 60 Hz tick; units are metres, Y up, a character at rest faces +Z; randomness only from the four seeded streams `map`, `encounter`, `reward`, `combat` (§3.2).
- `shared/` must not import DOM, Three.js, or any art path; assets are referenced only by logical ID such as `fx.fireball_travel` or `model.golem` (§3.1, §3.4).
- Elements in order `fire, water, earth, wind` (index 0 to 3, used by `swapTo`). Statuses `burning` 5 s, `soaked` 8 s (15% slow), `rocked` 8 s (+15% damage taken), `gusted` 1.2 s (§6.1).
- Player numbers (§4): move 6 m/s; dodge 0.4 s roll, 0.25 s invulnerable, 1.2 s cooldown, one charge; swap cooldown 0.4 s; swap-in bonus +25% damage for the next skill within 3 s; cast movement 70% windup and 50% channel; health 100; no mana.
- Reactions: 12 ordered combinations, 10 distinct effects; per-enemy per-reaction cooldown 0.75 s; the hit consumes the old status then applies its own (§6.2, §6.3). Enemy multipliers: weakness 1.5x, resistance 0.5x, immune to its own element's status (§6.4).
- Guard: 80% reduction except weakness; weakness hit does 1.5x and staggers out of guard for 2 s; reactions bypass guard (§8.2).
- Room budget `8 + 3 * roomIndex`; rewards 1 of 3 (skill, augment, heal); rarity weights rooms 1 to 3 common 70, rare 27, epic 3, later 40, 45, 15; at least one skill offer by room 3; no repeated skill offers in a run (§9).
- Render profile `chunky`: native resolution with user render scale 0.75 to 1.0, antialiasing on, nearest texture filtering for tiny textures, linear (smoothed) for sprites (§3.4).
- Clip format: 30 fps, Int16 quaternions (value / 32767) plus Float32 hips positions, base64 in JSON, bones listed per file.
- Versioning: versions stay below 1.0. Every task's commit runs `npm run bump -- "<note>"` (patch number +1, an entry at the top of `shared/data/patches.json`, README line 1, root and client `package.json`). Owner and dev tools are never listed in patch notes.
- Licences: `licenses.json` is checked on every build; unverified assets only warn until `LICENSE_GATE=enforce` is set (it is switched on before any public release). Raw downloads and the original Spellwoven pack are never committed.
- Before every push: `npm run typecheck` and `npm test` must pass.
- The staging folder (`/tmp/claude-0/-home-user/60552bea-0a23-5b6c-8ecc-5f70a35c71f2/scratchpad/staging/`) lives only in this container's scratchpad. Task 1 copies it into the repo; do that and push before anything else long-running.

## Review Focus

1. Aim at the sky or at nothing: the aim point must resolve to a point at maximum range along the ray (never NaN or undefined) and skills still fire (Task 12).
2. A room that rolls zero affordable enemies, or a reward pool where every skill is already owned: no softlock; the room still has enemies, the offer falls back to augment and heal (Tasks 31, 32).
3. A malformed, huge or rigless upload: refused with a plain message and nothing stored, no exception in the panel (Task 29).
4. A backgrounded tab: the worker must cap catch-up (at most 5 ticks per frame) so returning to the tab does not freeze (Task 6).
5. WebGL2, Workers or IndexedDB unavailable: a readable message on screen instead of a blank page or a crash (Tasks 8, 30).
